# 匿名演示版 Cloudflare 部署

生产 Worker 名为 `huijing`，匿名访问，无登录。下面的创建、远端迁移、secret、deploy、rollback 命令会写入 Cloudflare 账号。

## 环境与 secret

Node.js 24、pnpm 10.26.2，使用 lockfile 安装。Worker 必须设置两个 secret：

| Secret | 用途 |
| --- | --- |
| `VERTEX_API_KEY` | 站点自有 Vertex key；只调用 aiplatform.googleapis.com |
| `SESSION_SECRET` | 至少32字符的随机签名密钥；30天 HttpOnly/Secure/SameSite=Lax 访客cookie |

`SESSION_SECRET` 应保持稳定；更换会让已有 cookie 失效，访客无法再通过旧 cookie 访问原项目。示例见 `apps/edge/.dev.vars.example`，仅含占位值与公开默认配置。本地配置用 `APP_ENV=development` 才会放宽 Secure；生产必须是 `production`。

部署工具另需进程环境 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。它们是 CLI 凭据，不是 Worker secret。也可以用 `CLOUDFLARE_ENV_FILE` 指定仓库外私有文件（同名变量格式），用 `VERTEX_KEY_FILE` 指定含 `GEMINI_KEY='…'` 的私有文件；工具没有本机路径默认值。`SESSION_SECRET` 只从部署进程环境读取。不要把真实值放入命令参数、Git、日志、构建产物或前端变量。

## 本地准备

```bash
pnpm install --frozen-lockfile
pnpm test:edge
pnpm test:workspace
pnpm run deploy:dry-run
```

dry-run 不需要密钥或 Cloudflare 登录，不读取私有凭据文件，不调用 Cloudflare API。它构建 shared、HTTP 模式 web 和 Worker，运行 `wrangler deploy --dry-run --env production`，输出 `.deploy/wrangler.json`、`.deploy/bundle-summary.json` 和 `.deploy/bundle/`（全部被忽略）。配置里没有真实 secret。

`node scripts/check-deployment.mjs` 使用临时端口、独立 `.deploy/verify-state` 和随机测试签名密钥进行本地生产配置演练；检查静态页面、所有迁移、匿名 cookie 复用、独立访客和 API JSON。它只停止自己启动的进程，并清理独立数据库状态。现有3000/8787服务不受影响。

## 资源与绑定

| 资源 | 生产名称/类 | Binding |
| --- | --- | --- |
| D1 | `huijing` | `DB` |
| R2 | `huijing-assets` | `BUCKET` |
| Queue | `huijing-media` | `MEDIA_QUEUE`（同Worker消费） |
| SQLite Durable Object | `ProjectRoom` | `PROJECT_ROOM` |
| SQLite Durable Object | `ProviderGate` | `PROVIDER_GATE` |
| Static assets | `apps/web/out` | `ASSETS` |
| Cron | 每分钟恢复、每日03:17 UTC清理 | `*/1 * * * *`、`17 3 * * *` |

不需要 Container、Docker、Supabase、MCP、用户 API key 或访问令牌。DO 沿用已有 `v1` SQLite migration 标签，不要重命名或清空命名空间。

仓库 `apps/edge/wrangler.jsonc` 的 D1 `database_id` 全部是 `00000000-0000-0000-0000-000000000000` 占位值，没有 `account_id`。真实部署脚本按名称查询/复用或创建 D1/R2/Queue，再把实际 database_id 仅回填到被忽略的 `apps/edge/.deploy/wrangler.json` 的 `env.production.d1_databases[0].database_id`。不要把真实 ID 回填后提交到仓库。手工部署也必须在该生成配置中替换占位值；R2/Queue 按上述名称绑定，无需把它们的账号ID写进配置。

## 首次部署

下列命令会写账号，推荐先将两项 CLI 凭据和两个 Worker secret 注入部署进程环境，再从仓库根目录运行：

```bash
node scripts/deploy.mjs
```

脚本按以下顺序执行：查找/创建资源 → 生成仅含公开绑定的配置 → 全部远端D1迁移 → 构建HTTP前端与Worker → 部署Worker及静态资源 → 通过stdin写两个secret → 匿名身份冒烟。查询失败不当作资源不存在，任一步失败停止。首次部署到secret配置完成之间，业务API会返回503；完成secret步骤后才视为可用。

手工资源创建命令（在 `apps/edge` 内；仅资源不存在时执行）：

```bash
pnpm exec wrangler d1 create huijing
pnpm exec wrangler r2 bucket create huijing-assets
pnpm exec wrangler queues create huijing-media
```

先在仓库根运行dry-run生成配置，再按上节说明在 `.deploy/wrangler.json` 中替换生产D1 ID；随后在 `apps/edge` 内执行：

```bash
pnpm exec wrangler d1 migrations apply DB --remote --config .deploy/wrangler.json --env production
pnpm exec wrangler deploy --config .deploy/wrangler.json --env production
pnpm exec wrangler secret put VERTEX_API_KEY --config .deploy/wrangler.json --env production
pnpm exec wrangler secret put SESSION_SECRET --config .deploy/wrangler.json --env production
```

secret值通过交互stdin提供，不写入配置文件。迁移仅新增（M5为0008至0012），保留旧用户和旧认证列，但旧身份不接受登录也不转为访客。部署工具匿名冒烟只调用三次 `/api/me`，检查cookie复用与独立身份，不消费图片或文本。实际生图、WebSocket、Cron调度和公网隔离仍应在部署后抽查。

默认启用 workers.dev；自定义域名时配置路由，并用 `DEPLOY_BASE_URL=https://你的域名` 指定冒烟origin。`/api` 与 `/api/*` 优先进入Worker，不回退SPA；静态资源支持 `/p?id=…&thread=…`。Cloudflare入口必须提供可信 `CF-Connecting-IP`；本地缺该头的请求共享桶，不读取X-Forwarded-For。

## 额度与保留期

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `GUEST_DAILY_SETS` | `2` | 每 IP 每 UTC 日套图上限，含整套重出 |
| `GLOBAL_DAILY_IMAGES` | `150` | 全站图片上限 |
| `GUEST_DAILY_RUNS` | `30` | 每IP成功文本模型调用上限，含子任务 |
| `QUOTA_CLIENT_OPS_DAILY` | `100` | 每访客浏览器媒体登记上限 |
| `VERTEX_IMAGE_CONCURRENCY` | `2` | 全站图片模型并发 |
| `VERTEX_TEXT_CONCURRENCY` | `4` | 全站文本模型并发 |

`bash scripts/push.sh be` 只推送 be 分支。密钥泄露扫描只读取进程环境的 `VERTEX_API_KEY` / `GEMINI_API_KEY` / `CLOUDFLARE_API_TOKEN`，不读取密钥文件、不打印值；至少提供其中一个实际值用于扫描。

每日额度按UTC零点重置，非UTC+8。额度须为非负整数，`0` 关闭对应消费；并发须为正整数。前三项及客户端额度可通过部署进程同名变量覆盖。清cookie无法清除IP套数额度。每套单张重出累计最多3次、不占套数，但占全站张数。已受理套数不因出图失败或项目清理退还；图像失败按张退回。需要先应用迁移 `0014_set_quota.sql`，本轮仅准备配置和迁移，不执行远程操作。D1记录预留与结算，所有准入走同一个全站DO，预留占额度，重复结算幂等。上游429/明确拒绝不计额度，图片网络超时/5xx提交不确定保守计费且不自动重提。HTTP预检与异步任务错误都给出中文说明、`QUOTA_EXCEEDED_IP`/`QUOTA_EXCEEDED_GLOBAL` 和UTC `resetAt`。

7天未访问访客项目按每日Cron清理。项目/资源/线程访问和WebSocket ping刷新访问时间，后台事件不延长保留；仍在最近执行窗口的任务跳过，陈旧的等待输入任务会随项目清理。删除标记持久化，先删R2对象，再在D1事务删关联行，故障可重复执行；保留其他项目仍引用的历史共享对象。图片与provider-parts对象一并删除。额度记录保留，不因删除返还当天消费。项目元素总量本轮补齐5000个上限，由D1触发器覆盖所有写入；每批500条操作与上传20MiB保持原值。每日每轮最多100个项目，超过部分下轮继续。遗留注册用户的项目不属于本任务的访客清理范围。

## 模型、本地代理与日志

模型ID、白名单、备用链和并发配置见 `.dev.vars.example` 与 `wrangler.jsonc`。明确图片请求跳过文本规划；复杂工具任务仍受每IP文本额度限制。图片数N对应N次模型请求；结果尺寸按解码像素。

本地Google访问需要代理时，可在启动进程设置 `HTTPS_PROXY=http://127.0.0.1:<代理端口>`、`NO_PROXY=localhost,127.0.0.1` 并用Node `--use-env-proxy`；此地址只是开发示例，没有写死在代码。需要Worker开发转发时运行 `pnpm --filter @loomic/edge dev:proxy` 并在本地设置 `VERTEX_BASE_URL=http://127.0.0.1:8790`，只允许开发环境与loopback HTTP origin；生产禁止自定义上游。

真实Vertex实测可将仓库外key读入进程 `VERTEX_API_KEY`，在 `apps/edge` 运行 `node --use-env-proxy --experimental-strip-types scripts/m5-live.ts`；它使用隔离Miniflare，不操作账号、不动现有端口，仅保存状态、耗时和尺寸，不保存密钥/请求头/响应图片base64。

日志观测已启用。部署后只读日志命令（在apps/edge）：

```bash
pnpm exec wrangler tail --config .deploy/wrangler.json --env production --format pretty
```

不要记录cookie、secret、图片正文或完整模型请求/响应。打包预算沿用3MiB Worker模块，static assets与真实账号额度由部署轮次确认；dry-run通过不证明线上权限或可用性。

## 更新与回滚

更新前重新运行必要验证和dry-run，再部署。保留Worker版本ID与Git提交；迁移只新增。`SESSION_SECRET`不随每次部署随机更换。

以下回滚命令同样写账号，谨慎执行：

```bash
pnpm exec wrangler deployments list --config .deploy/wrangler.json --env production
pnpm exec wrangler rollback <VERSION_ID> --config .deploy/wrangler.json --env production
```

Worker回滚不会恢复已清理的D1/R2内容或回滚数据库迁移。M5以前的登录版不再符合产品方向，不作为匿名版本的常规回滚目标。

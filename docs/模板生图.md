# 模板一键出图（产品方向 v2）

2026-10-25 定。绘境收窄为一件事：**上传一张商品图，选一个模板，一键出一整套电商图**。聊天 Agent 保留但退为侧栏辅助，不是主入口。取消登录，匿名访客使用（见后端 M5）。

## 核心体验

1. 首页：拖入/粘贴/选择 1–3 张商品图 → 选模板卡片 → 可选在输入框补一句（"主打防水，给户外人群"）→ 点「一键生成」。什么都不填也能出。
2. 进入工作区：画布上按模板版式摆出整套占位（每张一个 frame），逐张出图逐张填入；右侧是「商品与卖点」面板，不是聊天。
3. 每张图的标题、卖点文字是**画布上的可编辑文字图层**，不由生图模型画进图里（模型写中文常出错）。底图只出无字画面，并为文字区留白。
4. 可以：改卖点文字（只改图层，不重出图）、单张重新生成、整套重新生成、下载全套（PNG/ZIP，文字图层合成进图）。

## 差异点（对外表述以此为准，不夸大）

- 零输入：视觉模型识别商品并提炼卖点，用户可改可不改。
- 成套一致：每张都以原图为参考，保持同一个商品。
- 文字不交给模型画：可编辑文字图层，错字直接改。
- Cloudflare 全托管：无服务器、无数据库运维，一条命令部署，在线演示免登录。

## 模板（数据，不写死在代码里）

模板是 `packages/shared` 中的数据文件，增删模板不改业务代码。首批 4 套：

| id | 名称 | 语言 | 张数 | 组成 |
|---|---|---|---|---|
| `amazon-7` | 亚马逊 7 图套装 | 英文 | 7 | 白底主图（无字，纯白 RGB255，主体占 85%）、卖点信息图 ×2、使用场景、细节特写、尺寸规格、包装清单/对比 |
| `taobao-detail` | 淘宝/天猫详情卖点 | 中文 | 6 | 首屏海报、卖点 ×3、使用场景、参数规格 |
| `xhs-seeding` | 小红书种草图 | 中文 | 4 | 大字封面、3 张生活方式场景配短句 |
| `quick-single` | 单张快出 | 跟随输入 | 1 | 白底主图或场景图二选一 |

模板结构：

```ts
type SetTemplate = {
  id: string; name: string; description: string;
  lang: "zh" | "en" | "auto";
  coverUrl?: string;                 // 首页卡片示例图，上线前用真实出图替换
  shots: Array<{
    id: string; name: string;        // 如 "卖点 1"
    kind: "main" | "selling" | "scene" | "detail" | "spec" | "compare" | "cover";
    aspectRatio: "1:1" | "3:4" | "4:3" | "9:16" | "16:9";
    sellingPointIndex?: number;      // 卖点图对应第几个卖点
    prompt: string;                  // 底图提示词骨架，可用 {product} {point} {scene} {audience} 占位
    textArea?: "top" | "bottom" | "left" | "right" | "none"; // 底图为文字留白的位置
    textSlots: Array<{ role: "title" | "subtitle" | "bullet" | "caption"; source: string; maxChars: number }>;
  }>;
};
```

## 接口（新增，不改已有语义）

- `GET /api/templates` → `SetTemplate[]`（去掉 prompt 字段）。
- `POST /api/sets` `{ sourceAssetIds: string[1..3], templateId, note?: string, sellingPoints?: SellingPoint[], lang?: "zh"|"en" }` → `{ setId, projectId, threadId }`。未给 `sellingPoints` 时服务端先做一次商品分析。按张数预扣额度，不足时整套拒绝并说明还能出几张。
- `GET /api/sets/:id` → `{ setId, projectId, templateId, state: "analyzing"|"generating"|"completed"|"partial"|"failed", analysis?: { productName, category, audience, sellingPoints: SellingPoint[] }, shots: Array<{ shotId, state, taskId?, frameElementId, imageElementId?, textElementIds: string[], error? }> }`
- `POST /api/sets/:id/shots/:shotId/regenerate` 单张重出；`PATCH /api/sets/:id/selling-points` 改卖点（服务端同步更新对应文字图层，不重出图）。
- 事件：`set.state`、`set.analyzed`、`set.shot`（含 shotId 与状态），沿用现有事件流与补发机制。
- `SellingPoint = { title: string; detail: string }`。

画布摆放：每张 shot 一个 frame，按模板顺序横向排列、行宽超过 4 张换行；底图放 frame 内，文字图层按 `textArea` 放在留白区，字体与字号由前端主题决定，服务端只给位置和内容。

## 联调补充（2026-10-26，M7 / 前端 M4）

M6 交付后补齐前端提出的缺口，两端按此实现：

- **项目 → 套图**：`GET /api/projects` 与项目详情的每个项目带 `setId?: string`；工作区据此直接取 `GET /api/sets/:id`，不再从画布反查。
- **改分析**：新增 `PATCH /api/sets/:id/analysis` `{ productName?, audience?, sellingPoints? }`，服务端同步改对应文字图层（规则同 selling-points：用户手改过的图层不覆盖）。旧的 `/selling-points` 保留为别名。
- **整套重出**：`POST /api/sets/:id/regenerate` `{ scope: "failed" | "all", clientOperationId? }`，按张预扣，额度不足整体拒绝。
- **状态推送**：前端改用事件流 `set.state` / `set.analyzed` / `set.shot`，不再 1.2 秒轮询；断线重连后补一次 `GET /api/sets/:id`。
- **shot 状态枚举**：以 `setShotStateSchema` 为准（queued/submitted/running/ingesting/completed/failed/cancelled）。
- **文字样式归属**：排版 token 在 `packages/shared/src/text-styles.ts`（`TEXT_STYLES` / `textStyleFor`）。服务端写文字图层时套用字号、字体、颜色、行高；前端负责调这份数值和留白区版式，改数值不改两端代码。
- **额度改为按套**：每 IP 每天 2 套（`GUEST_DAILY_SETS=2`），全站每天 150 张图不变；单张重出每套最多 3 次且不占套数；`/api/me` 返回 `setsRemaining`。
- **出图稳定性**：模型未返回图片时服务端自动重试 1 次，仍失败才标 failed；场景、细节、对比图不得与原图构图近似（需换角度/景别/背景）。

## M8 限流与排队（2026-10-26）

图片任务遇到 429/503 时，优先读取 `Retry-After`（秒数或 HTTP 日期）及 `google.rpc.RetryInfo.retryDelay`；两者都有时采用较长值。没有有效提示则采用指数退避加抖动，初始 5–10 秒、单次最多 60 秒。`PROVIDER_RETRY_MS` 可调整退避基数。`PROVIDER_RETRY_MAX_WAIT_MS` 默认 `180000`，限制单张累计排队等待（包含全站并发等待，不含模型实际生成时间）；队列延迟向上取整到秒，超过剩余预算立即结束，不提前违反上游等待提示。

退避计数、累计等待、无图重试标记和 `retryAt` 保存在 D1。任务回到 `queued`，通过持久化 outbox 及 `MEDIA_QUEUE.send(..., { delaySeconds })` 延迟重投，原消息确认；不在图片 Worker 内长时间 sleep，也不受旧消息 `max_retries=3` 限制。发送中断由 alarm/cron 恢复；重复投递受任务 claim 与 `retryAt` 保护。参考 [Queues 延迟投递文档](https://developers.cloudflare.com/queues/configuration/batching-retries/) 和 [Vertex 错误码](https://cloud.google.com/vertex-ai/generative-ai/docs/model-reference/api-errors)。

`GET /api/sets/:id` 的 shot、`set.shot` 和 `task.state` 事件新增可选 ISO 时间 `retryAt`，供界面显示“排队中”。套图（含单张重出）固定原图片模型，不进入 lite 降级链；非套图图片保留等待预算耗尽后的备用模型策略。主图优先发送；即使 Queue 调换消息顺序，同套其他 shot 也须等主图首次提交。全站图片并发由 `VERTEX_IMAGE_CONCURRENCY` 配置，默认 `2`；全站 DO 连续两次图片 429 后降至 `1`，最后一次 429 后经过 30 秒且连续成功至少两次，再逐级恢复到配置上限。

`shot.error.code` 区分 `RATE_LIMITED`、`NO_IMAGE`、`SAFETY_BLOCKED`、`UPSTREAM_ERROR`、`TIMEOUT`。安全阻断不当作无图重试；明确无图仍最多自动重试一次。限流失败退回图片额度；整次申请全部因限流失败时，也退回对应每日套数额度。503 是明确暂时不可用，可延迟重试；其他 5xx、网络中断或超时仍不自动重复未知提交，分别记录上游错误或超时。

上线需先应用新增迁移 `0015_image_backoff.sql`；本轮只在本地隔离数据库验证，不操作 Cloudflare 账号。

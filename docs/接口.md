## M7 模板一键出图

唯一产品需求为《模板生图.md》v2。模板、请求、响应与事件的 Zod 真源在 `packages/shared/src/set-templates.ts` 与 `edge-contracts.ts`。新增接口、字段和迁移 `0013_sets.sql`、`0014_set_quota.sql`。模板仅改数据即可增删，单套安全上限为 `MAX_SET_SHOTS=32`，实际仍受访客与全站额度限制；每行最多4张，行高按模板比例计算，9:16 长图也不与下一行重叠。

| 方法 / 路径 | 请求 | 响应 |
|---|---|---|
| `GET /api/templates` | 无 | `SetTemplate[]`，每个 shot 不含 prompt |
| `POST /api/sets` | `{sourceAssetIds:string[1..3],templateId,note?,sellingPoints?,lang?:"zh"\|"en"}` | 201 `{setId,projectId,threadId}` |
| `GET /api/sets/:id` | 无 | `{setId,projectId,threadId,templateId,state,analysis?,shots,lang?,error?}` |
| `POST /api/sets/:id/shots/:shotId/regenerate` | 可空；`{clientOperationId?}` | 202 `{setId,shotId,taskId}`，有操作 ID 时幂等 |
| `PATCH /api/sets/:id/analysis` | `{productName?,audience?,sellingPoints?:SellingPoint[3..5]}`，至少一项 | 更新后的套图详情 |
| `PATCH /api/sets/:id/selling-points` | 同 analysis，旧路径保留为别名 | 更新后的套图详情 |
| `POST /api/sets/:id/regenerate` | `{scope:"failed"\|"all",clientOperationId?}` | 202 `{setId,shots:[{shotId,taskId}]}` |

`SellingPoint={title,detail}`：中文标题最多12字，英文最多6词，说明最多30字符（英文含空格）。分析包含 `productName,category,audience,sellingPoints`。模板固定语言优先；quick-single 用显式 lang，其次 note 中有中文则 zh，否则 en。quick-single 默认白底，非空 note 且未指定白底时选择场景构图。供应卖点时跳过视觉分析，商品名/品类使用保守通称；不自动猜测其他信息。

state 为 `analyzing|generating|completed|partial|failed`。shots 每项 `{shotId,state,taskId?,frameElementId,imageElementId?,textElementIds,error?}`，单张状态为 `queued|submitted|running|ingesting|completed|failed|cancelled`。部分成功为 partial，全失败为 failed。原图须归属当前访客；复用时仅克隆资产引用到新项目，不移动或复制原图像素。其他访客访问、修改或重出均返回403。

创建套图及整套重出在全站单一 DO 内同时原子预扣 1 套及所选图片张数；每 IP 每 UTC 日 `GUEST_DAILY_SETS=2`，全站 `GLOBAL_DAILY_IMAGES=150`。失败或取消的图片退回张数，已受理的套数不退；创建数据库事务失败会退回整笔预扣。全站张数或 IP 套数不足返回429 `QUOTA_EXCEEDED_IP|QUOTA_EXCEEDED_GLOBAL`，details 有 `setsRemaining,availableImages,requested,resetAt`，不新增任务、不改变已有套图。套数记录在清理项目后仍保留。套图不受旧聊天图片限额影响。

整套重出保留原 setId/projectId、frames 和文字；`failed` 只选择 failed/cancelled 图片，分析失败时重新分析整套；无失败张为空操作，不占套数。`all` 替换全部图片任务。整套生成期间返回409。`clientOperationId` 在同一套图内幂等，换范围重用返回409。单张重出每套累计最多3次，计数跨日期、跨整套重出保留；只预扣1张全站额度，不占套数。失败保留旧底图。并发及重放不重复扣额。

模型成功响应但未含有效非 thought 图片时，同一任务持有原预留自动再调用1次（续期并发租约、不会重复扣张数或套数）；仍无图返回 `PROVIDER_ERROR`，message 明示已重试，details 含 `reason,noImageRetries:1`。空 candidates、无 content、仅文字、仅 thought 预览均属于无图。网络/5xx结果不确定仍保留原有不自动重提语义。429仍按指数退避重试，期间套图预留不会释放给其他任务抢占。文本并发与按 IP 日额度不变。

未供应卖点时，一次结构化视觉分析并经 Zod 校验；只对服务商明确限流/文本传输失败做既有传输重试，不做第二轮“修字”调用。对单凭外观无法证明的耐用、防水、透气、舒适、保温等性能词，若 note 未明确提供对应信息，则拒绝该分析并退额，不带着无依据文案继续生图。此检查不是完整语义证明，视觉实测的问题仍须如实记录。分析失败退回整套图片额度（套数不退）；崩溃后不重复不确定的分析执行。分析成功后每张同时入队，每张仍受全站图片并发上限（默认2）约束，outbox 与定时恢复可补发。

沿用项目事件流、seq、cursor、WebSocket及补发机制：`set.state {setId,state,error?}`、`set.analyzed {setId,analysis}`、`set.shot {setId,...shot}`。任务、画布、artifact 原事件同时保留。首个响应前创建占位 frame，横排每行最多4张。底图与文字分别是 frame 内元素；文字引用 `textStyleFor(role, frame.width)` 的 fontSize/fontFamily/strokeColor/lineHeight，按字号、估算换行数计算高度并依次排放；排版数值由前端维护 shared token。分析修改只同步关联文字，按修改前分析生成内容比对现有文字，用户手改或删除的图层不覆盖，也不重置其样式/位置；不调用模型、不增任务、不扣图额。后续重出使用最新分析。场景/细节/对比提示词要求新构图、背景或景别，细节必须为已见特征的近摄。导出合成由前端负责。

`GET /api/projects` 的项目及 `GET /api/projects/:id.project` 带 `setId?:string`；普通项目省略此字段。

子 Agent 整体默认45秒（`CHILD_TIMEOUT_MS` 可配置），超时持久化为失败且 `error.details.skipped=true`，事件 childState=skipped，质量保持 unchecked；必需检查超时也不阻塞 Run 结束。已移除无 role 的重复委派步骤。开发命名空间保留方案见《本地数据保留.md》。

旧 `POST /api/runs/:id/retry` 不用于 kind=set，返回409并指向整套/单张重出。旧 Run 取消入口在套图分析阶段可停止并退回图片预留；开始出图后返回409“套图已开始出图，请等待结束后再重出”，避免上游已执行图片仍被反复取消退款以绕过全站额度。该限制不改变既有聊天与媒体 Run 的取消语义。

## M5 项目元素总量保护

复查M4a发现只有每批500条画布操作限制，没有单项目元素总数限制。本轮补齐每项目5000个元素（含保留的删除标记），`GET /api/capabilities.maxProjectElements` 返回该值，shared导出 `MAX_PROJECT_ELEMENTS`。D1触发器统一覆盖用户、Agent和Task写入；超过返回 `CANVAS_LIMIT_EXCEEDED`，整批回滚。达到上限仍允许修改现有元素；可使用新项目继续。既有上传20MiB、单次操作500条等限制保持不变。

## M5 直出

明确生图请求直接创建 N 个图片任务，跳过文本规划与前置参考审查；明确改图/扩图在指定快照唯一时直接执行；单张原始上传可自动建立等价快照，保持归属校验，不要求重复上传。零次文本模型调用、每张图一次图片模型调用（429 重试沿用规则）。多目标排版、方案讨论、自动迭代仍走工具流程；缺目标图等不可执行情况才追问。界面 `settingsExplicitKeys` 优先，其余从文字提取。需要严格 margin/保留区恢复的扩图继续用 `/api/media/ops` 的 `expand`，聊天扩图属于模型语义编辑。

消息列表 `runs[].executionMode` 为 `direct` 或 `tools`。新 Run 对外不再发送 `planning` 状态，使用 `running` 配合 `summary=理解需求`，真实图片调用通过 `task.state=running` 标识；步骤显示“生成 N 张图”“编辑图片”等。`planning` 枚举仅为历史数据恢复兼容保留。直出默认不做额外视觉模型审查，明确要求检查时在图片完成后执行，不把未检查声称为通过。

真实 Vertex 单样本：受理 24 ms、进入生成 102 ms、总耗时 16.676 s，单次 `gemini-3.1-flash-image` HTTP 200，实际 1024×1024 PNG。证据 `docs/evidence/be-m5/vertex-live.json`，本地隔离 Workers 运行时加真实上游，不代表公网延迟分布。

## M7 每日额度与保留期

套图额度见文首：按 IP 每天2套、全站150张、每套3次单张重出。`GUEST_DAILY_RUNS=30` 仍限制每 IP 成功文本调用（包括子任务）。IP 取可信 `CF-Connecting-IP` 的哈希，无该头时共享 `local` 桶，不使用 X-Forwarded-For。

`GET /api/me.quota.setsRemaining` 为当前 IP 今日剩余套数（包含整套重出）；`used` 为访客已结算图片数，`globalRemaining` 包含预留扣减，`resetAt` 为下一个 UTC 零点。保留 `remaining,ipRemaining,limit,runsRemaining` 兼容既有客户端；默认图片余额受全站张数限制，旧聊天可单独配置 `GUEST_DAILY_IMAGES`，套图不使用此限制。`0` 关闭对应消费。

每日 Cron `17 3 * * *` 清理 7 天未访问的访客项目、关联 D1 记录和 R2 文件；最近仍在执行的 Run/Task 跳过，陈旧的等待输入任务会随项目清理，访问项目、资源、线程或 WebSocket ping 更新访问时间，后台事件不算访问。删除标记可在故障后重试；当天额度不会因清理返还。每分钟 Cron 保留任务恢复。

## M5 匿名身份（本轮契约覆盖旧认证章节）

首次 `/api/*` 请求自动创建访客，签发 `session` 签名 cookie（HttpOnly、Secure、SameSite=Lax、30 天；开发 HTTP 可不设 Secure）。`SESSION_SECRET` 至少 32 字符。cookie 无效或过期会创建新访客，不能恢复旧归属。项目、资源、线程和 WebSocket 仍按 `user_id` 隔离。

`GET /api/me` 返回 `{user:{id,name,isGuest:true},quota:{used,limit,globalRemaining,resetAt}}`。注册、登录、注销、会话查询接口均删除，`/api/auth/*` 返回 404。旧用户不自动转为访客。数据库迁移只新增，旧认证列保留但不接受密码。

# Cloudflare 后端接口 v1（至 M4a）

唯一机器契约：`packages/shared/src/edge-contracts.ts`，导入 `@loomic/shared/edge`。旧 `@loomic/shared` 根入口暂保留给旧服务；新前端不要混用旧协议。

## 相对草案的明确差异

- 所有业务接口自动建立匿名访客会话；`/api/auth/*` 已删除。身份与额度以文首 M5 契约为准。同源 Origin 检查继续覆盖 HTTP 与 WebSocket。
- `POST /api/projects/start` 首次 201、相同 submissionId 重放 200。幂等范围为用户；相同 ID 不同规范化正文 409 `IDEMPOTENCY_MISMATCH`。返回 `{projectId,threadId,runId}`。
- `settings` 缺省为 `{count:1,aspectRatio:'auto',quality:'standard',modelId:'auto'}`。文字中的明确数量、比例和高质量要求可覆盖默认值；与 `settingsExplicitKeys` 冲突先进入 `waiting_input`。自然语言识别并非完整语义解析器；未识别冲突不得视为已验证能力。
- start/messages 可传 `viewportCenter:{x,y}` 冻结无源图结果的起点；未传则为画布坐标原点。编辑图使用源元素的世界 AABB；旋转后仍按右侧 48 单位放置。整批避让不覆盖用户已经手动移动的先完成结果。
- `POST /api/threads/:id/messages` 返回 `{messageId,runId}`，clientMessageId 同线程幂等；活动 Run 通过 D1 部分唯一索引限制。消息分页使用 `before=messageId`。返回 `{items,runs,tasks,inputRequests,before}`，历史原始模型 parts 仅在服务端保存，API 不发送 thought 或签名。
- `GET /api/projects/:id` 额外返回 `eventCursor`。画布 files 为 `{[fileId]:{assetId}}`，fileId 为 Asset ID，资源字节从鉴权的 `/api/assets/:id` 读取，前端自行构造 Excalidraw BinaryFiles。
- canvas 操作中每个 element 必须有 `id,type,x,y,width,height,version`。文件引用只能为本项目 Asset。baseRevision 过期时只在操作涉及的元素发生改变时 409；不同元素可合并。409 的服务端版本在 `error.details.{revision,serverElements}`。clientOpId 同项目幂等，服务端规范化并递增元素 version。
- `/api/snapshots` 使用 JSON（直接复用原图、appearance 为空）或 multipart（`metadata` 是 snapshotRequestSchema JSON、`file` 是渲染后的 PNG）。有外观修改时必须附 PNG；renderKey 同用户去重且校验内容 hash。上传允许 `projectId`；不传则属于用户草稿，首次提交在 D1 事务内认领。
- 新增 `GET /api/projects/:id/events?cursor=N`，返回 `{items}`，至多 1000 个事件，便于诊断和 HTTP 补读；实时通道仍是草案 WebSocket。seq 项目内连续递增；连接时在同一 DO 写门内补发。cursor 不能超过当前序号。
- `artifact.committed` 中包含 `{artifact:{id,taskId,asset,snapshotId},elementIds,revision}`；生成结果自动建立可引用快照，后续对话可使用 read_canvas 返回的 snapshotId。取消后迟到产物仅存储，不发送 committed、不插图。
- 新产物含 `artifact.mode:fixture|vertex`，前端据此标注演示结果；历史兼容允许该字段缺省。
- Task、Run 状态采用简化版本；有部分 Task 失败时 Run 为 failed，已成功产物保留，通过 tasks 区分部分成功。
- M1 Agent 工具只有 `read_canvas`、`generate_images`、`edit_image`、`ask_user`。每轮最多一批媒体任务、12 次工具调用、10 分钟主动执行预算。三类审查子 Agent 仍属后续里程碑；浏览器算法由另一任务实现，本服务只负责登记结果。
- `POST /api/media/ops` 和 `POST /api/media/client-results` 已实现，参数与限制见下文。`POST /api/tasks/:id/retry` 要求 `{clientOperationId}`，返回 `{taskId,runId}`，只重试失败/取消项，保留原冻结输入，创建新 Run/Task；同操作 ID 幂等。并发活动 Run 未结束时返回 `RUN_ACTIVE`。提交不确定也只有此显式新执行路径能重试。

## M2a：429 退避与降级

每个模型最多请求 4 次；前三次 429 按指数退避并尊重 `Retry-After`。图片仍为 `RATE_LIMITED` 时，只有 `settingsExplicitKeys` 不含 `modelId` 才进入图片降级链；文本 Agent 独立使用自己的备用链。图片链由 `IMAGE_FALLBACK_CHAIN` 配置，默认 `gemini-3.1-flash-image,gemini-3.1-flash-lite-image`；自动编辑/高质量原先使用 Pro，遇限流从链首 Flash 开始。文本链由 `AGENT_FALLBACK_CHAIN` 配置，默认 `gemini-3.8-flash,gemini-3.1-flash-lite`。配置为逗号分隔的模型 ID；空字符串关闭该链。

每次切换模型发 `run.step`；图片的 `summary` 为“高峰限流，已改用快速模型”，文本为“文本模型暂时不可用，已切换备用模型重试”。图片 Artifact 的 `modelId` 为实际成功模型。显式选型或整条链均耗尽时失败为可重试的 `RATE_LIMITED`。明确拒绝不计额度；同一 Task 的成功结果只计一次。网络超时、图片 5xx 等提交不确定错误仍禁止自动重提或降级。

## M2a：服务端媒体操作

`POST /api/media/ops`，访客及项目归属校验后返回 **201 `{taskId,runId,threadId}`**。通过既有 `GET /api/tasks/:id`、项目事件获取结果。`clientOpId` 同用户幂等，不同正文复用返回 409。异步执行复用 SubmitIntent、队列、取消、重试与唯一插入逻辑。一次操作只产出一张图，按图片任务计额度。

```json
{
  "clientOpId": "uuid",
  "projectId": "project_x",
  "threadId": "thread_current",
  "source": {"elementId": "element_x", "snapshotId": "snapshot_x"},
  "op": "edit",
  "params": {"prompt": "把杯子改为蓝色"},
  "settings": {"modelId": "auto", "quality": "standard"},
  "settingsExplicitKeys": []
}
```

`settings` 可省略，沿用生图默认值；本接口固定 count=1。快照、源元素和遮罩必须属于当前用户及项目；源元素必须引用快照的来源资源或渲染资源。坐标是快照像素，原点左上；区域不得越界。

| op | params |
|---|---|
| `edit` | `{prompt}`，Quick Edit 指令 |
| `replace_text` | `{regions:[{x,y,width,height,text,newText}]}`；`text` 是原文，每个区域给新文字。提示词包含坐标、原文和新文字；区域参数 JSON 总长至多 24000 字符 |
| `multiview` | `{azimuth,elevation}`，角度分别为 -180～180、-90～90 |
| `move_object` | `{srcBox:{x,y,width,height},dstBox:{x,y,width,height}}` |
| `expand` | `{margin:{top,right,bottom,left}}`，非负整数像素，至少一边大于 0 |
| `erase_ai` | `{maskAssetId}`；遮罩和快照尺寸相同。不透明且 RGB 均值 ≥128 的像素是编辑区，其余均保留 |

`expand` 在 Worker 中解码快照，按 margin 放进透明大画布后发模型；返回后按原位置贴回全部原图 RGBA。`erase_ai` 向模型发送快照和遮罩，返回后贴回非编辑区原 RGBA。两者输出都编码为无损 PNG。模型返回尺寸若与目标画布不同，先检查原始结果未超处理上限，再只对生成的填充图重采样到目标尺寸，最后贴回原 RGBA；原图像素不参与缩放。超过处理上限的模型结果直接失败，绝不先缩小绕过上限。

服务端媒体处理限定 **4,194,304 像素、单边 4096、单文件 8MiB**。输入在入队前检查，模型结果在解码分配前再检查；超限为 **422 `MEDIA_LIMIT_EXCEEDED`**（异步结果超限见 Task.error），不静默缩小。上限已通过独立本地 workerd 的 4MP 解码、适配、原像素贴回与编码实测；证据见 `docs/evidence/be-m4a/media-bench.json`，未部署到 Cloudflare。选择高质量不保证结果可通过该上限。

每个产物保留 `provenance:{sourceSnapshotId,op,params}`，并建立新快照。画布插入使用源图世界 AABB 右侧 48、长边 360、避让规则；产物的实际像素尺寸保持原值。

## M2a：浏览器处理结果登记

`POST /api/media/client-results`：去背景、LaMa 消除、OCR、矢量化、超分算法在浏览器运行。服务端验证并持久化结果，不运行这些算法、不计生图额度。

```json
{
  "clientOpId": "uuid",
  "projectId": "project_x",
  "op": "remove_bg",
  "sourceSnapshotId": "snapshot_x",
  "params": {},
  "engine": {"name":"birefnet", "version":"1.0", "modelSha256":"64位小写十六进制模型hash"},
  "result": {"assetId":"asset_result"}
}
```

`engine` 三个字段均必填，hash 必须是 64 位小写十六进制；它是客户端声明的运行记录，服务端不宣称能证明浏览器实际运行了该引擎。

| op | result | 服务端检查 |
|---|---|---|
| `remove_bg` | `{assetId}` | 与快照同尺寸，PNG/WebP 带 alpha 通道 |
| `erase` | `{assetId}` | 与快照同尺寸的位图 |
| `upscale` | `{assetId}` | 宽、高均增加，宽高比例完全一致 |
| `ocr` | `{ocrRegions:[{x,y,width,height,text,confidence?}]}` | 区域为快照像素且不越界；confidence 为 0～1；最多 1000 区域 |
| `vectorize` | `{svgAssetId}` | 静态 SVG、与快照同尺寸 |

结果资源必须已通过 `/api/uploads` 上传，并显式指定当前 `projectId`，快照也必须归属当前项目。位图结果重新解码校验，最大 **4,194,304 像素、单边 4096**；超限 `MEDIA_LIMIT_EXCEEDED`。SVG 上传上限 2MiB，只接受静态图形标签与属性子集（支持 vtracer 的 path），拒绝脚本、事件、外部链接、foreignObject 和样式。`params` JSON 至多 16000 字符，结果元数据至多 128000 字符。

成功返回 **201 `{artifact,revision,elementIds}`**，并发 `artifact.committed`。浏览器 Artifact 的 `taskId:null`，`provenance` 包含 `{sourceSnapshotId,op,params,engine}`。图像/SVG 结果建立新快照并按源图放置；OCR 的 `asset:null,snapshotId:null,ocrRegions:[...]`，`elementIds:[]`，画布 revision 不增加，也不发 canvas.ops。Task 查询中的 Artifact 继续要求图片，未放宽旧 Task 契约。

`clientOpId` 在用户范围幂等：相同规范化请求返回同一 Artifact 和 revision，不重复插图、发事件、计次；不同请求为 409 `IDEMPOTENCY_MISMATCH`。`QUOTA_CLIENT_OPS_DAILY` 默认 100，以 UTC+8 自然日计数；跨项目并发由 D1 触发器和事务保证总上限，额度不足返回 429 `QUOTA_EXCEEDED`。校验失败不计次，登记、计次、来源链、画布修改和事件在同一事务提交。

`GET /api/capabilities` 新增 `clientOperations`、`mediaLimits`，`operations` 包含上述六种服务端操作；`models` 包含配置的图片降级模型。`assetSchema.mime` 新增 `image/svg+xml`；事件中的 Artifact 允许浏览器结果形态，前端需处理 OCR 无图情况。

## 开发与部署

`pnpm --filter @loomic/edge build` 只做本地 esbuild + WASM 打包，不访问 Cloudflare 账号。

`pnpm --filter @loomic/shared build` 后运行 `pnpm --filter @loomic/edge dev:vars`。密钥脚本只读取本机指定文件，不打印密钥；`.dev.vars`、`.local/`、`.wrangler/` 被 apps/edge/.gitignore 排除。

进入 apps/edge，在设置 `HTTPS_PROXY=http://127.0.0.1:<代理端口>` 后运行 `node --use-env-proxy scripts/vertex-proxy.mjs`；代理只监听 loopback，只转发固定 Vertex generateContent 路径。`APP_ENV=development` 才允许 `VERTEX_BASE_URL` 指向 `http://127.0.0.1:<端口>`，生产禁止自定义上游。

在 apps/edge 运行 `pnpm dev --var PROVIDER_MODE:vertex` 启动真实模式。启动脚本在 `.local/` 生成配置：有前端 out 时使用它，否则使用 edge/public，API 不依赖前端构建。production 使用 apps/edge/wrangler.jsonc 的命名环境，通过根目录 `scripts/deploy.mjs` 查询/准备资源并生成有效配置，再注入 `VERTEX_API_KEY`；可选 Turnstile 两项配置必须同时提供。详情见 [部署手册](部署.md)。生产拒绝 Turnstile 测试 secret；未配置验证码时使用严格注册 IP 限速。本轮未执行公网部署。本地如需验证码测试，可显式配置官方测试 sitekey `1x00000000000000000000AA` 与测试 secret，来源见 [Turnstile 测试文档](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)。PBKDF2-SHA256 使用独立随机 salt、100,000 次迭代（[workerd 平台上限说明](https://github.com/cloudflare/workerd/issues/1346)）；会话只在 D1 存 token 的 SHA256。

`pnpm smoke` 运行真实冒烟，`SMOKE_MODEL_ID` 可明确指定配置允许的模型。失败记录应先归档再重试；`node scripts/smoke.mjs --resume` 是显式手动恢复入口，复用 `.local/` 中的临时会话，只重试失败项、不重复生成已完成首图。成功后删除该临时会话文件，证据目录永不包含 cookie。

迁移：`pnpm exec wrangler d1 migrations apply huijing --local --config .local/wrangler.json --persist-to .wrangler/state`。线上加 `--remote`，使用正式配置。每天额度以 UTC+8 自然日计；先预留防止并发超额，429/明确拒绝释放，成功或无法确认上游是否接受时计数。未知结果保守计数，绝不自动重提。

完整 Agent contents、parts、functionCall.id、thoughtSignature 存 D1；图片模型返回的大体积 parts 原文放 R2，artifacts.provider_parts 存指针，避免 D1 单行限制。R2 不开放公网访问。

基础设施参考：[Cloudflare WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)、[Static Assets 绑定](https://developers.cloudflare.com/workers/static-assets/binding/)。

## M4a：文本模型重试

文本模型遇到网络错误或 HTTP 5xx 时，在同一模型上最多重试 3 次（首次请求加 3 次重试），指数退避 1/2/4 秒，并尊重秒数或 HTTP 日期形式的 Retry-After。重试耗尽才按 AGENT_FALLBACK_CHAIN 切换；HTTP 4xx（429 除外）不重试、不降级。最终错误为 PROVIDER_ERROR、retryable:true，提示用户重试。界面 settings.modelId 仅选择图片模型，不限制文本 Agent 的备用模型。

图片请求的限流策略已由 [M8 限流与排队](模板生图.md#m8-限流与排队2026-10-26) 更新：429/503 使用延迟队列退避，网络错误、其他 5xx 和超时不自动重提，错误码分别为 `UPSTREAM_ERROR` / `TIMEOUT`。

`POST /api/runs/:id/retry` 请求 `{clientOperationId}`，恢复失败 Run 的文本阶段，返回 `{runId,state:'planning'}`。仅支持 `PROVIDER_ERROR/RATE_LIMITED` 且 `retryable:true`、无失败/未完成媒体任务的 Agent Run；仍使用原 runId、完整 contents 和已完成图片，不重新生图。同操作 ID 幂等；同线程有其他活动 Run 返回 `RUN_ACTIVE`。图片失败继续使用 `/api/tasks/:id/retry`，创建新的图片执行；不确定提交的原语义保持不变。

## M4a：模型、恢复数据与事件

`GET /api/capabilities.models` 默认包含 `gemini-3.1-flash-image`（标准）、`gemini-3-pro-image`（高质量）与 `gemini-3.1-flash-lite-image`（快速草图）。`IMAGE_MODEL_ALLOWLIST` 可用逗号分隔配置完整白名单；未配置时包含上述三档及显式配置的图片 fallback 模型。显式白名单优先于 fallback 链；不在白名单中的请求在建 Run/入队前返回 422，fallback 也不会调用被排除的模型。

`GET /api/threads/:id/messages` 保留原字段，新增：

- 用户消息 `references:[{snapshotId,purpose,order,thumbnailUrl}]`，引用冻结于提交时，顺序值原样返回；`thumbnailUrl` 为受当前登录会话鉴权的快照预览资源 URL，快照无法找到时为 null。
- 用户消息 `settings`（提交设置）、`settingsExplicitKeys`、`effectiveSettings`（服务端解析/确认后的设置）。待规划时 effectiveSettings 暂为提交设置；用户确认冲突后反映最终设置。旧分页消息也回显对应的冻结提交。
- `runs[]` 增加 `error`、`steps`、`timings`。steps 为该 Run 所有持久化 `run.step` payload，加 `seq,at`，按 seq 排序，包含同一步的 started/completed/failed 变化；客户端可按 stepId 折叠。timings 是 `run.timing` payload，加 `seq,at,taskId?`。数据来自 D1 事件日志，不依赖 WebSocket cursor 或 localStorage。
- `tasks[].slot:{x,y,w,h}`，排队时冻结于 task.input；长边 360、横向间隔 32、源图右侧 48、整批避让已有元素及其他待完成 slot。比例由已确认设置或媒体目标尺寸估算。结果到达后按实际像素与放置规则确定尺寸，已完成任务返回当前结果矩形。旧任务无 slot 时该字段可缺省。

新增事件：

| type | payload |
|---|---|
| `thread.created` | `{thread:{id,projectId,title,createdAt,isSystem}}` |
| `message.created` | `{messageId,threadId,role,createdAt}`；用户、工具规划中的助手消息和最终助手消息各发一次 |
| `run.timing` | `{phase,durationMs,startedAt,label,requestBytes?}`；phase 为 read_canvas/model/tool/image/ingest/review |

`task.state.payload` 新增可选 `slot`，queued 时即带冻结预估；committed 时带实际矩形。图片手动重试也重新按当前画布冻结 slot 并发 queued 事件。`run.state.payload` 新增可选 `phase,summary`，等待文本模型时发明确阶段说明；已有 state 语义不变。创建通知在 DO 写门内按实体去重，HTTP 写入后崩溃可在 wake、快照或 WS 重连时补发；最终助手消息与其创建事件在同一事务写入。已有 message.final 继续发送。

服务端在 Run 开始时预读一次仅含元数据的画布，并随首轮用户内容交给模型；模型可直接创建图片任务，排版写入前仍须 read_canvas 获取最新 revision。模型返回的全部 parts、thoughtSignature 和 functionCall.id 继续原样持久化/续传。各阶段实测见 `docs/evidence/be-m4a/README.md`。

## M4a：媒体线程、元素 index 与 fixture

`POST /api/media/ops` 新增可选 `threadId`。传入时校验属于当前项目并把 Run 挂入该线程；不新建线程，也不改变当前 lastThreadId。该线程存在活动 Run 时返回 409 `RUN_ACTIVE`。未传则创建 `isSystem:true` 的“图片后处理”线程；普通线程为 `isSystem:false`。响应始终为 `{taskId,runId,threadId}`，幂等重放返回相同身份；迁移前的旧幂等记录会按 Task/Run 补齐身份。

服务端写入的新图片、浏览器登记结果、Agent 文本与 frame 均带 Excalidraw 兼容的 fractional `index`；Agent reorder 同时更新 index。生成批次插入保留既有元素顺序和 index。

fixture 不再输出 1×1 图片：默认 1:1；标准长边 1024、高质量长边 2048，按 aspectRatio 计算另一边。支持中英文红/蓝/绿/黄/紫/橙，其他提示词使用稳定颜色，输出带边框与中心色块的 PNG。它用于核对颜色、比例和放置，不模拟真实图像语义。媒体 fixture 按目标画布尺寸出图，供源像素保留测试使用。

迁移 `0007_m4a.sql` 给 threads 新增 is_system，并给按 Run 读取事件建立索引。未更改 apps/web；本轮测试全部使用独立 Miniflare 数据与随机端口。
